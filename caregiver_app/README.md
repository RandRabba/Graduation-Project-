# Caregiver Module (Flutter)

Caregiver mobile interface for the **Diabetes Monitoring and Meal Analysis System**.
It is a Flutter port of the Caregiver prototype, built as a **self-contained module**
so it can run on its own now and be pushed from the existing Patient app later.
The Patient app and the Doctor dashboard are not touched.

- Flutter widgets and Dart only (Material 3), no external state-management package
- Read-only by design: no add, edit or delete of readings, meals, reminders or medications
- Basic and Extended monitoring
- Light and dark mode
- English (LTR) and Arabic (RTL)
- Realistic mock data behind a repository interface

## Run it

Requires Flutter 3.24 or newer (Dart 3.5+).

The ZIP contains `lib/`, `pubspec.yaml` and `analysis_options.yaml` only, because platform
folders (`android/`, `ios/`, ...) are generated by the Flutter tool. Recommended:

```bash
flutter create --project-name caregiver_app caregiver_run
# copy these from the ZIP over the new project, replacing what is there:
#   lib/   pubspec.yaml   analysis_options.yaml
cd caregiver_run
flutter pub get
flutter analyze
flutter run
```

(`flutter create --project-name caregiver_app .` inside the unzipped folder also works, but
check afterwards that `lib/main.dart` and `pubspec.yaml` are still the ones from this project.)

Fonts: *Plus Jakarta Sans* (English) and *IBM Plex Sans Arabic* (Arabic) are loaded with the
`google_fonts` package. That needs internet the first time. For **release builds on Android**
add `<uses-permission android:name="android.permission.INTERNET"/>` to
`android/app/src/main/AndroidManifest.xml` (the debug manifest has it already). For production,
download the font files and bundle them as the `google_fonts` package documents, so the app
works offline. Without network, the app falls back to the system font and keeps working.

### Using the demo

1. The login fields are pre-filled in demo mode. Tap **Log in**.
2. You land on the **invitation** screen. Tap **Accept invitation**, then **Open dashboard**.
3. The small round button at the bottom corner (demo mode only) opens **Prototype controls**:
   access level (Basic / Extended), theme, language, data state (loading, old reading, no
   reading, no alerts, error, access revoked, no linked patient), invitation state
   (pending, expired, declined, revoked, accepted) and the role returned after login.
4. Language and dark mode are also real settings under **Profile**.

## Basic vs Extended

| | Basic | Extended |
| --- | --- | --- |
| Patient name, status, emergency contact | yes | yes |
| Latest glucose reading (with time and "may not be current" note) | yes | yes |
| Alerts | **critical only** | all |
| Reading history, chart, filters, HbA1c | no ("Not shared with you") | yes |
| Health reports, reminders, doctor instructions | no | yes |
| Diabetes type, assigned doctor | hidden | shown |
| Notification switches | critical only (always on) | critical + high, low, repeated, reminders |

Restricted data is gated **in the data layer**: `CaregiverRepository` returns empty/null for
Basic, so a restricted screen never holds the data. The caregiver can never change the level
(only the patient can). **In production the backend must enforce this too**: the API should
not send restricted data at all.

Other safety decisions: opening an alert never marks it resolved; guidance on alerts is
generic and says it is not medical advice; classification chips carry a symbol (✓ ↑ ↓ !) so
colour is never the only signal; charts always run left to right, also in Arabic.

## Integrating into the Patient app

1. Copy the whole `lib/caregiver/` folder into the Patient app's `lib/`.
2. Add the dependencies from this `pubspec.yaml` if missing: `flutter_svg`, `google_fonts`,
   and `flutter_localizations` (SDK).
3. Push the module from wherever the Patient app handles the caregiver role:

```dart
import 'caregiver/caregiver.dart' as caregiver; // alias avoids name clashes (Patient, Reminder, ...)

Navigator.of(context).push(MaterialPageRoute<void>(
  builder: (ctx) => caregiver.CaregiverModule(
    repository: ApiCaregiverRepository(session), // your FastAPI-backed implementation
    showDemoControls: false,                      // hide prototype controls
    startAtDashboard: true,                       // host already signed the caregiver in
    onExit: () => Navigator.of(ctx).pop(),
    onCall: (phone) => launchUrl(Uri.parse('tel:$phone')), // url_launcher in the host
  ),
));
```

4. Implement `CaregiverRepository` (`services/caregiver_repository.dart`) against the FastAPI
   endpoints, and delete the use of `MockCaregiverRepository`. The interface is the only
   place the UI gets data from. Methods are synchronous in this demo; switch them to
   `Future` (and add loading handling in the controller) when you call a real API.
5. Login, registration, email verification and the invitation screens are UI only. Wire them
   to your auth endpoints, or skip them with `startAtDashboard: true`.
6. The module has its own `MaterialApp`, so it brings its own theme and language and does not
   inherit the host's. If you prefer to share one app-wide language/theme, the controller's
   `arabic` and `dark` flags are the only things to bind.

## Deliberate differences from the prototype

- A language link ("العربية" / "English") on the sign-in screens, so Arabic speakers do not
  need to log in first to change language.
- In demo mode, the login fields are pre-filled and a round demo-controls button replaces the
  prototype's side panel.
- After "Disconnect from patient", the Profile connection card shows "No linked patient"
  instead of still saying the patient is linked.
- Alert details opened from Home stay in the Home tab (the prototype switched the highlighted
  tab to Alerts).
- Dates and times come from a fixed mock clock (Fri 30 Oct 2026, 08:30) so the demo reads
  the same on any day. "x min ago" is computed from it.

## Known limitations

- Call, PDF download, support contact and password change are placeholders (a message is shown).
- Mock authentication: any non-empty email/password signs in; no tokens or persistence.
- Settings (language, theme, notification switches, edited profile) are in memory only.
- No automated tests yet: `google_fonts` fetches fonts at runtime, so widget tests need
  `GoogleFonts.config.allowRuntimeFetching = false` or bundled fonts.
